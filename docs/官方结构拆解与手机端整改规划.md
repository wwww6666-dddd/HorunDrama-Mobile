## 1. 官方是怎么把这么大的东西组织起来的

### 1.1 工程规模（实测）

| 指标 | 数值 |
| --- | --- |
| APK 体积 | 156,400,488 B（仅 arm64-v8a） |
| dex 数量 / 类总数 | **26 个 / 350,223 个类** |

### 1.3 三个值得抄的结构点（都有类名实证）

1. **剧场是"模型驱动的瀑布流"，不是固定布局**
   - `pages/bookmall/model/BookMallCellModel`（含 `AdModel`/`RankDataModel`/`TopicItemModel`/`RecentReadModel`/`VideoTabModel` 等子模型）
   - `feed/bookmall/card/model/staggered/InfiniteCell` + `InfiniteModel` → 无限流卡片
   - `pages/bookmall/place/SlideListPlacer` + `PlaceUtilsKt` → 卡片**定位/占位**独立成层
   - `feed/bookmall/common/DoubleRowMarginConfig` → 双列边距是**可配置项**
   - **启示**：官方把"一张卡长什么样"和"卡片怎么排"拆开了。我们 `views/Theater.tsx` 只有 2KB、`mobile/pages/Home.tsx` 6KB，是"页面里写布局"，没有模型层。

2. **底部 Tab 是配置出来的**
   - `feed/bookmall/bottomtab/SeriesMallPageConfig`（+`BackDispatch`）→ 底栏 tab 由配置对象描述
   - `assets/main_bar_lottie/{polaris,category,bookmall,bookshelf,mine}[_dark].json` → 每个 tab 一套选中动效
   - **启示**：官方能随时调 tab 个数与顺序；我们 `mobile/nav.tsx` 的 `TABS` 是硬编码 5 项。

3. **播放器与弹幕是两个包，播放器还有"会话"概念**
   - `video/BaseVideoView`、`video/IVideoDataProvider`、`video/VideoDetailModel`、`video/TouchDirection`、`video/VisibleType`
   - `video/api/ISessionPlayAction`（`Reason` 枚举）→ **连播/上下集是"会话级动作"**
   - `video/danmaku/` 一整个子包（含 `VideoDanmakuAbHelper$tryFetchBlockedWordConfig`）
   - **启示**：我们 `views/Play.tsx` 单文件 50KB、`PlayerBarExtras.tsx` 17KB、`ui/DanmakuLayer.tsx` 4KB，播放/弹幕/控制条耦合在一个文件里。

4. **官方有专门的平板适配层**：`IStorePadAdapt` / `StorePadAdapt` / `SearchBarKmp`
   - 我们直接在平板上跑手机布局（这次扫描就是覆盖成 392×851dp 才对齐），**没有 pad 分支**。纯净版可以先不做，但要在文档里留位。

## 2. 我们现在的结构 vs 官方

| 维度 | 官方 | 我们 | 判断 |
| --- | --- | --- | --- |
| 客户端形态 | 原生 Compose + Lynx 混排 | WebView + React（`apps/mobile-web`） | 形态不同，不改 |
| 数据层 | RPC + `sources/origin` | Node 核心 `http/api.ts`（42KB）+ `sources/*`（12 个文件） | ✅ 结构已对齐，保持 |
| 页面组织 | 单 Activity + 模块化页面（`pages/*` / `polaris` / `leftslidepage` / `video`） | `MobileApp.tsx` 路由表 + `mobile/pages/*` + 复用桌面 `views/*` | ⚠️ 页面按"业务"分，没按"页面域"分；桌面视图被手机端硬复用 |
| 底栏 | 配置驱动（4 个纯文字 Tab） | 硬编码 5 个图标 Tab（`mobile/nav.tsx`） | ❌ 要改 |
| 剧场列表 | 双列瀑布流 + CellModel + Placer + 混排卡 | Hero 大卡 + 横向 rail（`views/Theater.tsx` 2KB / `Home.tsx` 6KB） | ❌ 要重做 |
| 播放 | `BaseVideoView` + `IVideoDataProvider` + session action + 独立 danmaku 包 | `views/Play.tsx` 50KB 单体 + `XgPlayer.tsx` | ❌ 要拆 |
| 弹幕 | 独立包，默认开启，覆盖在黑边区 | `DanmakuLayer.tsx` 嵌在播放页 + `design/danmaku.css` | ⚠️ 位置与层级要改 |
| 我的 | `leftslidepage` 独立模块，浅色 | `mobile/pages/Me.tsx` 13KB，深色设置式列表 | ❌ 要重构 |
| 视觉体系 | 浅色为主 + 黑白灰 + 字体承担层级 | 深色玻璃 + 强调橙 + 大标题 | ❌ 方向要换 |
| 素材 | 字体 + lottie 规范 | 系统字体 + 自绘图标 | ⚠️ 可引入字体 |
| 福利/广告 | `goldcoinbox` / `ad` / `ug` | 仍有残留：`ui/RewardDialog.tsx`、`design/reward.css` | ❌ 纯净版应移除入口 |

## 3. 纯净版边界（明确不做）

| 官方模块 | 处理 |
| --- | --- |
| `goldcoinbox`（福利金币）、福利 Tab | **不做**，底栏不设福利位 |
| `ad`（开屏/激励/信息流广告）、`StaggerCardReporter` 曝光上报 | **不做**，接口层不接广告位字段 |
| `bookmall` 商城、`minigame`、`social` 社区、订单 | **不做** |
| 支付（`ttcjpaysdk`）、会员/VIP | **不做** |
| 青少年模式（`teenmode`） | **暂不做**（无账号年龄体系） |
| 推送（`push`） | **C 档**：沿用 PC 核心的新集检查，手机独立运行时由本机执行 + 本地通知；不接厂商通道 |
| 热修复（Tinker/gecko） | **C 档**：只做前端 `dist` 热更 + 哈希校验，不做原生补丁 |
| 多进程 | **C 档**：`:player`/`:downloader` 拆分，先评估收益（当前单进程未成瓶颈） |
| Lynx/H5 动态页（`hybrid`、`com/lynx/tasm`） | **C 档**：远程 HTML + 域名白名单 + 不给 JS 桥；不引全量 Lynx SDK |
| 小说/听书/漫画/POV 文本（`reader`、`audio_*`、`story`） | **C 档**：前置是验证 `openhongguo` 是否暴露这些域，验证不过就不做 |

**保留清单**：首页推荐流、剧场、搜索、榜单、播放、详情、我的（历史/收藏/点赞/预约）、下载、设置。

> 边界已于 2026-11-25 13:47 调整：推送、热修复、多进程、Lynx/H5 动态页、小说/听书/漫画/POV 由"不做"改为 C 档（可做、后续单独立项）。它们**不进本次 UI 主线**，但接口前缀、路由、页面目录、数据表已按《开发文档》§1.2 的扩展位约定预留。

## 4. 整改规划

> 原则：**先动信息架构，再动页面结构，最后动视觉资产**。每一阶段做完即可独立验收、独立发版，避免一次性推倒。

### 阶段 A · 信息架构对齐（P0，约 1.5 天）

#### A1 底栏改 4 个纯文字 Tab

官方是 `首页 / 剧场 / 福利 / 我的`；纯净版去掉福利，补上"追剧"作为第四位：

```
首页(feed)  ·  剧场(home)  ·  追剧(library)  ·  我的(me)
```

- 选中态 = **字重 + 颜色反转 + 1px 下划线**，不用胶囊、不用图标。
- 改动点：
  - `apps/mobile-web/src/mobile/nav.tsx`：`TABS` 从 5 项改 4 项（去掉 `rank`），`MRoute` 保留 `rank` 供深链；
  - `apps/mobile-web/src/mobile/MobileApp.tsx`：`TabBar` 去掉 `<Icon>`，`m-tabbar__pill` 改为下划线；`TAB_ROUTES` 同步；
  - `apps/mobile-web/src/mobile/mobile.css`：`.m-tabbar*` 重写（高度 44dp、字号 17sp、无图标）；
  - `apps/mobile-web/src/routes.ts` + `mobile/nav.tsx` 的 `ALIAS`：保留 `#/rank`、`#/settings`、`#/theater` 映射，**老分享链接不能 404**。
- 验收：4 个 tab 等宽、无图标；`#/rank` 仍能进榜单页；分享链接 `#/play/...` 不变。

#### A2 榜单/搜索/追剧的入口重分配

官方把榜单放在「剧场 → 排行榜」和「搜索 → 榜单区」，追剧放在「我的 → 追更」。

| 功能 | 新入口 |
| --- | --- |
| 榜单 | 剧场页第 2 个胶囊「排行榜」；搜索页底部榜单区 |
| 搜索 | 首页右上放大镜 + 剧场页顶部搜索框（两个入口同一页） |
| 追剧 | 底栏第 3 位（纯净版保留独立 Tab，比官方更好找） |
| 下载 | 我的 → 快捷卡「下载」 |
| 新剧日历 | 剧场 → 胶囊「新剧」 |
| 设置 | 我的 → 右上菜单 |

#### A3 顶栏收敛

- 首页（feed）：去掉大标题，左侧汉堡菜单（打开 = 我的/设置入口抽屉）、右侧搜索。
- 其它页：统一 `‹ 返回` + 居中标题（现在的 `m-topbar` 已具备 `data-compact`，只需改 `MobileApp.tsx` 的标题策略：tab 页不再显示大标题）。
- 验收：首页首屏不再出现「剧场」之类的大标题；所有页顶部高度一致（44dp + safe-area）。

### 阶段 B · 页面结构对齐（P0/P1，约 3 天）

#### B1 首页推荐流：16:9 居中 → 黑边 → 通栏剧集条

- `apps/mobile-web/src/views/Feed.tsx`（45KB）：
  - `--feed-media-h` 从 `100vw`（1:1）改为 `min(100vw, 100vw * 9 / 16)`，视频居中，上下留黑；
  - 右侧 rail 去底板：只留白色线性图标 + 数字（图标 23dp、数字 10sp）；
  - 左下信息瘦身成 `@作者` + 一行简介 + 「展开」，删掉集数徽标与标签堆；
  - 底部改为通栏剧集条：`漫剧·剧名·全N集 ›`（现在是胶囊，改成左右内缩 9dp 的通栏）。
- `apps/mobile-web/src/design/feed.css`（12KB）+ `mobile/mobile.css`：同步 `feedv__frame / feedv__info / feedv__rail / danmaku-layer` 的 `top`，**这次正好复用《UI修改规划.md》里的 `--feed-media-h` 变量方案**。
- 顶部 tab 组：`关注 / 漫剧 / 真人剧 / 推荐` 改文字 + 下划线，去胶囊。
- 验收：390×844 与 360×800 下视频 16:9 居中，信息区 ≥180dp，右侧 4 个操作全部可点。

#### B2 剧场页：去大标题 → 搜索框 → 分类行 → 4 胶囊 → 双列瀑布流

- 新建列表组件（建议 `apps/mobile-web/src/mobile/pages/Home.tsx` 内）：`MasonryGrid`，2 列、列宽 187dp、间隙 7dp、外边距 7dp，海报 3:4。
- 卡片规格（照官方）：海报 → 剧名 2 行 13sp → 标签 chips（16dp 高，橙字「评论破4万」/ 灰字品类）。
- 混排件（官方有三类，建议我们先做两类）：
  1. `继续播放` 卡（白底圆角，进剧集）；
  2. `爆款新剧` 左上角标 + 海报左下 `💧热度`；
  3. `榜单入口` 金色胶囊卡（第 2 行插入，点击进榜单）。
- 数据：复用 `apps/mobile-core/src/sources/catalog.ts` 的分区数据，前端只做排序与混排，不再另建接口。
- 验收：一屏可见 ≥4 张卡；继续播放卡只在有进度时出现；标签超长截断。

#### B3 搜索页

- 顶部：圆角搜索框 + 右侧「搜索」；保留 `pages/Search.tsx` 现有接口。
- 快捷 chips：`识剧`（改成**粘贴链接解析**，复用 `ShareDialog.tsx` 的解析逻辑，不引入图像识别）、`排行`、`上新`。
- 搜索历史：本地存储 + 两列 + 清空；猜你想搜：热词 3 卡。
- 榜单区：`热搜榜 / 预约榜` 两个 Tab（官方第三个"热点话题榜"我们没数据来源，不做）。
- 验收：无网络也能看到历史；点击热词直接出结果页。

#### B4 我的页

- 结构（浅色）：渐变头 → 头像 + 昵称 + 本地 ID（不显示红果号）→ 三数字（**收藏 / 追更 / 下载**，不造"粉丝/获赞"）→ 快捷卡 4 个（下载 / 收藏 / 追更 / 设置）→ 内容 Tab 4 个（历史 / 收藏 / 点赞 / 预约）→ 二级 chips（全部 / 已看完 / 未看完）→ 3 列海报网格。
- 官方 `作品` Tab（UGC 发布）**不做**。
- 改动：`apps/mobile-web/src/mobile/pages/Me.tsx`（13KB）整体重写；设置项从"整页列表"改成"快捷卡点进去的二级页"（`pages/Misc.tsx` 承接）。
- 验收：4 个 Tab + 4 chips 切换不闪屏；空态文案与官方一致（"还没有记录，去看剧吧"）。

#### B5 播放页

- 顶部：`‹ 第N集` + 右侧 `⋮`（菜单里放：举报/分享/下载）。
- 右侧 rail：实心五角星（收藏）/ 三点气泡（评论）/ 心（点赞）/ 折角箭头（分享），**全部去底板**。
- 左下：剧名（22sp 粗体，可点进详情）→ `第N集｜简介… 展开` → `ⓘ 作者声明`（我们自己不加这条，替换为"内容来自红果"）。
- 底部：细进度条 + 4 控件 `选集 ⋯ / HD 清晰度 / 1.5x / 清屏`，删掉现在的五按钮操作栏。
- 弹幕：默认开启，覆盖在**视频上方的黑边区**，不再压画面。
- 改动：`apps/mobile-web/src/views/Play.tsx`（50KB）拆分 → `mobile/player/PlayerChrome.tsx`（顶部/底部控件）+ `mobile/player/PlayerRail.tsx`（右侧）+ `mobile/player/PlayerInfo.tsx`（左下信息），`DanmakuLayer.tsx` 调整定位。
- 验收：320 宽 4 个控件全见；弹幕不遮挡字幕；进度条可拖。

## 6. 取舍建议（哪些官方做法不要照抄）

1. **不要复刻"配置驱动底栏"**：官方要 A/B 和远程开关，我们是自用纯净版，`TABS` 常量表就够，留一个 `settings.json` 的开关位即可。
2. **不要引 lottie**：底栏 5×2 套动效体积换不来体验，字重 + 下划线更轻，也更符合"文字 Tab"的视觉。
3. **不要做"识剧"图像识别**：改成"粘贴红果链接 → 解析 → 预览"（`ShareDialog.tsx` 已有能力），成本差一个数量级。
4. **不要抄"作品/UGC"**：没有社交与发布链路，做了也是空页。
5. **不要抄平板双栏**：官方有 `StorePadAdapt`，我们这次是覆盖成手机尺寸采样；纯净版先单列，pad 适配留到后面。

## 8. 风险

1. **底栏一改，所有深链都受影响**：必须先落 `ALIAS` 映射表再动 UI，`#/play/...`、`#/mini/...` 完全不动。
2. **16:9 会让首屏信息区变高**：`--feed-media-h` 变量方案在《UI修改规划.md》里已验算过（375×667 → 261dp），直接复用，不要重算。
3. **浅色主题动 4 层 CSS**（`tokens` / `v2` / `feed` / `mobile`），回归面最大，**放最后一步**；且推荐流与播放页必须保持黑，不能跟着翻白。
4. **拆 `Play.tsx` 时** `PlayerBarExtras` / `XgPlayer` / `ShareDialog` 互相引用，拆完要跑一次真实播放（当前只有一条 5.84s/123.44s 的进度记录，属于弱验证）。
5. **官方 UI 会持续变**：7.4.5.32 是当前样本，后续若官方改版，本规划里的具体尺寸（16:9、44dp、187dp 列宽）需要按新截图复核。
