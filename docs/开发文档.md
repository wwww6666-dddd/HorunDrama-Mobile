## 0. 这份文档和 v1 的关系

v1 开发文档描述的主线是「1.1.0 独立化」（把 Node 核心搬进 APK）。那条线现在**重启为发布阻断项**：代码在，1.1.1 已补真 ffmpeg 并上真机（D-23/D-24 关闭）；只剩 A0-4 登录→播放→下载未验，过之前不得发版（见 §16 阶段 A0）。

v2 把工程明确拆成**两条独立推进的线**，避免互相干扰：

| 线 | 内容 | 状态 | 是否本次主线 |
| --- | --- | --- | --- |
| **A 线：运行时** | 模式 A（PC 核心 + 局域网 WebView）→ 模式 B（APK 内置 Node） | A 可用；B **1.1.6** 已装模拟器（双 ABI/壳子/深链/B3/B4/B5/C），A0-4 登录→下载→新集未验 | **是，发布阻断**（"手机独立运行"是硬要求） |
| **B 线：界面与信息架构** | 以官方 7.4.5.32 为基准，重做导航、剧场、推荐、我的、播放、搜索 | B1 feed ✅ / B2 剧场 ✅ / B3 我的 ✅ / S1 壳子 ✅ / B4 播放 ✅ / B5 搜索 ✅ / C 字体与图标 ✅ | **B/C 已收口，剩素材替换** |

两条线必须**在同一版本里同时达标**：UI 对齐是「看起来对」，独立运行是「用起来能活」。凡本文出现「本次」「大改」，默认指 B 线；A 线单独验收，但**独立运行不达标不得发版**。

> **方案口径（2026-11-25 用户确认，后续按此执行）**
>
> 1. **取流/登录不在手机端另写**：手机内置核心与 PC 端 `apps/core` 是同一份源码。`appplay.ts`、`sms.ts`、`session.ts`、`account/index.ts`、`http/api.ts`、`app-source.js`、`playback-device.js`、`playback-sign.js`、`pure-sign.js` 逐文件 SHA-256 一致；`sources/client.ts` 只做运行时适配（端口、独立核心、签名地址），不改协议。以后升级取流或登录，只改 PC 那份，手机端同步拷贝。

## 1. 产品定位与边界

### 1.1 定位

**短剧为核心的内容客户端**：当前只做「找剧—看剧—追剧」这一件事，以官方红果短剧的信息架构与视觉为参照，去掉一切与观看无关的商业模块。后续可扩展到小说 / 听书 / 漫画 / POV 文本（C 档，见 §1.2），但**短剧始终是唯一主线**，扩展不改变底栏与信息架构。

### 1.2 能力边界（三档）

**A 档 · 明确不做（写死，不接受"先加上再说"）**

| 官方能力 | 处理 |
| --- | --- |
| 福利页 / 金币 / 现金提现 / 打卡任务 | **不做**，底栏不设福利位 |
| 开屏广告、激励视频、信息流广告位、曝光上报 | **不做**，接口层不接广告字段 |
| 商城（bookmall）、游戏（minigame）、社区动态、订单 | **不做** |
| 支付 / 会员 / VIP / 钻石 | **不做** |
| 青少年模式 | **暂不做**（无账号年龄体系，等账号链路稳定后再议） |

**B 档 · 本次大改做（B 线）**

首页推荐流、剧场（找剧/筛选/榜单/新剧/预约）、搜索、播放（弹幕/评论/倍速/选集）、详情、我的（历史/收藏/点赞/预约）、追剧、下载、设置。

**C 档 · 可以做，但后续单独立项（不进本次 UI 主线）**

| 能力 | 定位 | 接入前必须先解决的事 |
| --- | --- | --- |
| 推送（新集提醒） | 阶段 D | **沿用 PC 核心那套，不自建厂商通道**：核心已有新集检查（`notifyNewEpisodes`），手机独立运行时由本机核心定时检查 + 本地通知；PC 在线时也可由 PC 侧检查后走现有接口同步。**前提是模式 B 达标——推送不许依赖"PC 一直在线"** |
| 热修复 | 阶段 D | 前端天然可热更：远端 `dist` 清单 + 哈希校验 + 原子切换（核心本来就托管 `dist`）；**原生层不做 Tinker 类补丁**，只做壳内资源与前端替换 |
| 多进程 | 阶段 D | 播放/下载拆 `:player`/`:downloader` 需 AIDL/Messenger；SQLite WAL 已能多进程，但当前核心是单 Node 进程，拆之前要先评估收益（现在单进程并未成为瓶颈） |
| Lynx/H5 动态页 | 阶段 D | 低成本方案＝远程 HTML + 域名白名单 + **不给 JS 桥**；真上 Lynx 引擎要引 SDK 与包体（官方那套 1,583 类的 `com/lynx/tasm` 不建议照搬） |
| 小说 / 听书 / 漫画 / POV 文本 | 阶段 D | 上游 `openhongguo` 是否暴露这些域**尚未验证**，这是前置；验证通过后需新增 `sources/novel|audio|comic`、阅读器（字号/夜间/翻页）与音频播放器（后台播放 + `MediaSession`） |

#### 扩展位约定（C 档接入时的硬规则，现在就把位留出来）

1. **API 按域挂**：`/api/novel/*`、`/api/audio/*`、`/api/comic/*`、`/api/push/*`、`/api/ota/*`，不塞进现有目录接口。
2. **路由按域开**：`#/novel`、`#/audio`、`#/comic`、`#/pov`，与 4 个底栏 Tab **解耦**——底栏不因为新增域变长。
3. **页面按域建目录**：`pages/novel`、`pages/audio`…（见 §4.2），沿用"一个域一个目录"的重组原则。
4. **设置只加不写死**：新增开关一律进 `settings.json` + `/api/settings`，前端读配置，不在组件里硬编码。
5. **数据表按域分**：`novel_progress` / `audio_progress` 独立于 `progress`，短剧进度不被别的域污染。
6. **任何新增域都不得把广告位、福利、曝光上报字段带进接口**——A 档边界优先于 C 档便利。
7. **所有能力必须在"无 PC 在线"下自洽**：登录、数据、推送、阅读/收听进度都不许回落到 PC 核心；PC 只作为可选加速与调试环境。

### 1.3 运行模式

- **模式 A（开发/调试用）**：电脑跑 `mobile-core`，手机 WebView 经局域网加载 `dist`。手机与电脑同一 Wi-Fi，电脑关机则手机不可用。**仅用于开发期联调，不作为交付形态。**
- **模式 B（目标形态 · 硬要求）**：APK 内嵌 Node 24 + 核心 + 前端 + ffmpeg，手机 `127.0.0.1:5881` 独立运行。1.1.2 包已含真 `libffmpeg.so`（8,264,272 B），已在 TGR-W10 启动；剩 A0-4 登录/播放/下载验收。
- **"手机独立运行"的具体口径**：拔掉电脑 / 关 Wi-Fi / 飞行模式（本地网）下，仍能启动、保留登录态、播放、下载、收到新集提醒；登录走 PC 端同款**手机号 + 短信验证码**（`/api/account/login/send-code` → `/api/account/login/sms`），数据接入沿用 PC 端同款 `openhongguo` App 源，不新开通道。

B 线与本文的 UI 改造无耦合：前端始终只走 `/api/*`，界面层不需要知道核心跑在哪台机器上（这一点必须守住，否则模式切换会撕开两套 UI）。

### 1.4 调试环境（2026-11-25 用户确认，后续按此执行）

1. **先不往手机上安装**：不再向 TGR-W10 平板 / 真机推 APK，也不再用 `adb install` 覆盖真机版本。真机只保留用户自己决定安装的历史包，不作为本轮验收环境。
2. **统一在电脑 Android 模拟器里测**：B 线每完成一页，构建 → 安装到 PC 上的模拟器 → 在模拟器里点按、截图、验布局与交互；模拟器是当前唯一 APK 安装与实拍环境。
3. **模拟器必须可见**：启动带窗口的 Android Emulator（不要 `-no-window`/headless），窗口保持在前台可见；每次测试把模拟器画面或截图同步给用户，让用户能看到当前进度，不只在后台跑命令。
4. **真机恢复条件**：只有在用户明确说“可以上真机/平板”之后，才恢复真机安装与实拍验收；在此之前所有“已上真机/平板”的旧结论仅作历史记录，不作为 B4/B5 的验收依据。

## 9. 核心链路（B 线不动这里，改动需单独评审）

### 9.1 播放决策（`media/jobs.ts`）

`/api/play/:episodeId` 返回 job（ready / queued / working），前端轮询 `/api/prepare/:jobId`。优先级：

1. 本地转码命中（`mode=file`）→ 立即 ready；
2. 指定高清未命中但低档已缓存 → 先播低档 + **后台**升档（`attachUpgrade`，不阻塞响应）；
3. 官网 360p 直连（`/api/stream/:episodeId` 代理，浏览器直连会 403）→ 立即 ready + **后台**升档；
4. `wait=1` 且以上都没有 → 起 App 源前台任务，前端轮询；
5. 秒开流（`/api/live`，无完整时长、不可拖）；
6. 慢路径：整集下载 + ffmpeg 转码。

关键约束（**重构界面时不许碰**）：同集同档 `INFLIGHT` 合并；前台转码不限并发、后台一次一个；升档后原位换源并保留播放位置；默认 `quality=1080p`，`wait` 由前端按场景传——手机端播放页与推荐流都传 `0`（先 360p 秒开、后台升清，见 §9.8）。

### 9.2 转码（`media/transcode.ts`）

`取流 → 下载加密原件 → ffmpeg → .part.mp4 → 时长/box 校验 → rename`。
进度 0~0.45 下载、0.45~0.99 转码、1 完成。能 copy 就 copy（H.264 或可硬解 HEVC 时 `-c copy`）；编码器 `h264_nvenc → h264_amf → libx264`，必须真编一帧才算可用；产物校验 `mvhd` 时长差 ≤3s、`moov` 恰好 1 个。

### 9.3 缓存

| 缓存 | 上限 | 清理 |
| --- | --- | --- |
| 转码视频 | 4096MB（`settings.mediaCacheMB`） | 完成后 `pruneMediaCache`；`/api/cache/clear` 只删受管文件名 |
| 封面 | 96MB | LRU |
| 直连地址 | 内存 400 条 / 提前 60s 过期 | 403 时重取 |
| 目录数据 | 内存 TTL | **首页/推荐流 180s**（阶段 0 由 120s/60s 上调，限流期靠缓存顶住首屏）；搜索联想 60s、详情/榜单 120s |

> 已知：`CACHE_LIMIT` 在模块加载时固化，改上限需重启（D-07）。

### 9.4 账号与本地库

- 三类身份分开：`app-device.json`（匿名）/ `session-device.json`（账号设备）/ `session.json`（登录态，可选 AES-256-GCM）。
- 写操作顺序：**先写账号，成功再改本地**；收藏失败回滚本地。
- SQLite（WAL）：`progress / favorite / liked / follow / reservation / download`；`progress` 以剧为主键，只记"看到哪集、第几秒"。
- **退出登录会清空本地 5 张表**（D-03），大改中必须改成"只清会话"。

### 9.5 下载

并发 1~4（默认 2）；优先 App 源转码，失败退 360p 直连；路径 `<downloadDir>/<剧名>/第N集-<档位>.mp4`；暂停/取消用 `AbortController`；恢复从 0 重下（D-13）。

### 9.6 上游失败与退避（阶段 0 新增，界面重构时不许回退）

`sources/client.ts` 的 `withRetry` 是所有目录类调用（首页/推荐流/搜索/筛选/榜单/详情/弹幕）的统一入口，策略集中在这里，调用方不再各自 sleep：

| 项 | 值 | 理由 |
| --- | --- | --- |
| 尝试次数 | 默认 **3**（播放链路显式传 1） | 限流/空响应多为瞬时；播放要立刻退化到 360p，不能干等 |
| 退避 | 800ms 起、`2^n` 递增、**8s 封顶**、±15% 抖动 | 固定间隔会形成同频重试；抖动把并发请求错开 |
| 上游建议 | 有 `retryAfterMs` 时取「退避值 / 建议值」较大者（同样 8s 封顶） | 尊重服务端，又不为一个目录请求挂几十秒 |
| 设备轮换 | 仅 `ANONYMOUS_LIMITED` / `DEVICE_REJECTED` 调 `client.resetDevice()`（重写 `data/app-device.json`） | 匿名空结果换身份才有用；`RATE_LIMITED` 换身份无效（实测） |
| 轮换冷却 | **90s** 内只换一次 | 每次失败都注册新设备会连着打注册接口，反而更像异常客户端 |
| 判为瞬时 | `ANONYMOUS_LIMITED` / `RATE_LIMITED` / `DEVICE_REJECTED` / `TRANSPORT` / message 含 empty·timeout·ECONNRESET | 参数错误、已下架必须原样抛出，不许吞 |
| 目录缓存 | `home` 180s、`feed` 180s（其余 60~120s） | 宁可给 3 分钟前的榜单，也不给空屏 |

上游最终仍失败时，接口照旧返回 `429 upstream_limited` / `502 upstream_down`，前端按错误态展示——**不要把失败伪装成空列表**。

### 9.7 红果分享链接与「识剧」（D-49，1.1.9）

**背景**：官方分享有两种形态，短链本身不带剧号：

| 形态 | 例子 | 参数含义 |
| --- | --- | --- |
| 完整分享页 | `https://novelquickapp.com/hongguo/ug/pages/video-animation-share?video_id=…&vid=…` | `video_id` = 剧（series），`vid` / `share_toast_vid` = 集（episode）；`no` / `t` 为本软件附加的集号与起播秒 |
| `/s/` 短链 | `https://novelquickapp.com/s/ndoHDfOcT-U/` | 无剧号，必须 302 到完整分享页后才能解析 |
| 老式带 `book_id` | `...?book_id=…&video_id=…` | `book_id` = 剧，`video_id` = 集 |
| 本软件 hash | `#/play/<seriesId>/<episodeId>/<no>?t=` | 剧 / 集 / 集号 / 秒 |
| 裸文本 | `<剧id> <集id> [集号] [秒]` | 手工调试兜底 |

**前端流程**（`apps/mobile-web/src/share.ts`、`ui/ShareDialog.tsx`）：

1. 输入框接受**整段分享文案**；`extractShareUrl()` 取第一个 `http(s)://` 地址，遇到空白、中文、全角空格、中文标点即截断，并去掉结尾的 `.,;:!?`。这样即使单行 `<input>` 把换行吞成空格，URL 也不会粘上后面的“复制本条消息”。
2. `parseSharedLink()` 先认本软件 hash，再按 query 解析 `book_id` / `video_id` / `vid` / `share_toast_vid` / `no` / `t`；只有集 id、没有剧 id 时直接判失败（无法反查剧号）。
3. 直解失败且 `isShortShareLink()` 为真时，前端显示「正在展开红果短链…」，调用 `GET /api/share/resolve?url=`，拿到最终 URL 后再走第 2 步。
4. 成功后请求 `/api/series/:id` 补齐标题、封面、集数；链接没给集号时按本地进度或第 1 集挑选。结果先出预览卡，用户点“继续观看”才跳转。
5. 展开成功、预览卡渲染前执行 `setNote('')`，避免「正在展开…」残留在结果页。

**核心展开**（`apps/mobile-core/src/sources/shareLink.ts`）：

| 项 | 规则 |
| --- | --- |
| 允许域名 | `novelquickapp.com` / `www.novelquickapp.com` / `iesdouyin.com` / `www.iesdouyin.com` / `douyin.com` / `www.douyin.com`；跳转后的域名也必须命中 |
| 起始路径 | 必须匹配 `^/s/[A-Za-z0-9_-]+/?$`；非 `/s/` 链接直接 400 |
| 跟随 | `redirect: 'manual'`，最多 **4** 跳；只跟随 3xx 的 `Location`，相对地址按当前 URL 解析 |
| 超时 | 单跳 `AbortSignal.timeout(10_000)`；不携带账号 Cookie，纯匿名请求 |
| 兜底 | 200 且不是跳转时，只在响应体里找红果域名且带 `video_id`/`book_id` 的链接；找不到即 422 |
| 缓存 | 以原始短链为 key，内存缓存 **10 分钟**；重启即失效，不落盘 |
| 拒答 | 任意非红果 URL、非 `/s/` 路径、跳转到站外，一律拒绝，避免本地接口变成 SSRF 代理 |

**错误码**：`400 share_url`（没找到/格式错）、`400 share_path`（不是 `/s/`）、`400 share_host`（非红果域名）、`422 share_target`（短链没跳到分享页 / 展开后无剧号，通常已失效）、`502 share_network` / `502 share_redirect` / `502 share_status`（网络、跳转地址或上游状态异常）。前端统一显示「解析失败：<message>」，不跳转、不写进度。

**验收基线（1.1.9）**：

- 真实文案：`漫剧《末日游戏：全民典狱长求生》… https://novelquickapp.com/s/ndoHDfOcT-U/ …` → 核心 `ok:true`，最终 `video_id=7703929325866716185` / `vid=7703929328911780926`；`/api/series` 返回 **191 集**；预览卡「末日游戏：全民典狱长求生 / 第 1 集 / 共 191 集 · 从头开始」。
- 回归项：完整分享页、本软件 `#/play/…`、裸文本三种直解路径不得退化；非红果域名必须 400；短链失败不得影响普通链接解析。
- 平板 `TGR-W10` 实机（1.1.9）复验通过，`note` 为空、预览卡正常。

**打包注意**：只改核心源码时，`build.ps1` 不会自动刷新 `.tmp\runtime-stage\assets\core\src`，必须先同步该目录（或重跑 `prepare-runtime.ps1`，再补 `prepare-runtime-x86.ps1` 的 x86_64 `libnode.so`），否则 APK 内仍是旧核心，表现为「没有这个接口: /api/share/resolve」。

### 9.8 播放体验五件事：与电脑端（`D:\红果短剧`）对齐的口径（1.2.0）

电脑端"秒开 / 缓存一批集 / 连续播放不卡 / 切集顺 / 还能上 1080p"不是单个开关，是五个机制叠出来的。1.2.0 逐条比对后，手机端补齐了真正缺的两处，其余沿用同源实现。

| 目标 | 电脑端的做法 | 手机端 1.2.0 | 代码 |
| --- | --- | --- | --- |
| 秒开 | 本地缓存命中 <0.1s；未命中时 `startEpisode` 先解析官网 360p（`/api/stream` 同源代理、保留 Range），高清后台转 | 同左，且**修掉"等高清才返回"**：`attachUpgrade` 改为不阻塞，`/api/play?quality=1080p&upgrade=1` 冷缓存实测 **8.5s → 0.36s** | `media/jobs.ts` |
| 缓存集数 | `preloadCount=5` → 前后各 5 集、串行、世代号、前台优先；电脑端实际攒了 **153 个文件 / 1.86GB**（119 集 1080p） | 同一套 `preload.ts`；新增 `scripts/seed-media-from-pc.ps1`，把电脑端已转好的集**硬链接**过来（不复制、不额外占盘，删除互不影响）；PC 核心这条线立刻命中 1080p | `media/preload.ts`、`scripts/seed-media-from-pc.ps1` |
| 连播不卡 | 播到 25s `prewarm(下一集)` + `startUpgrade(下一集)`；预加载串行 | 播放页同左；**推荐流**补"停留 2.5s 预热下一条"（feed 没有剧集列表，按滑动顺序算），快速划走会取消 | `views/Play.tsx`、`views/Feed.tsx` |
| 切集流畅 | 不清 `job`、只暂停不卸载、等待卡压暗旧帧、就绪原地换源、进度按 `currentSrc` 集号校验 | 同左；新集通常直接命中 360p，切集从"转圈几十秒"变成通常 **1s 内出画面** | `views/Play.tsx` |

**与电脑端有意不同的两处**：

1. 手机端播放页 `wait=0`（电脑端是 `wait=1`）。手机独立运行时转码跑在手机 CPU 上，等文件等于每次切集都转圈几十秒；官网 360p 是 H.264 明文且支持 Range，先播它既秒开也能拖。
2. 推荐流首帧也走 360p 秒开（电脑端推荐流仍 `wait=1`）。刷流场景没有"等"的耐心，高清在后台补。

**1.2.0 实测（PC 核心 · 5881）**：

- `GET /api/play/<ep>?quality=1080p&upgrade=1`：冷缓存 **360ms** 返回 `mode=direct / 流畅 360p`；`auto` **4ms**。
- 硬链接复用后，命中缓存的集 `mode=file / 1080p` 返回 **3~52ms**。
- `/api/home` 冷启动 **8.9s → 5.1s**（并行发 `discover`/`newReleases`，第 2 页与补详情移出关键路径，补详情最多等 1.2s）。
- 推荐流 390×844 实拍：首帧直接出画面 + 「流畅画面已开始，正在准备高清…」胶囊；热度胶囊显示真实点赞（如 `🔥 44.3万 赞`）。
- 独立 APK 1.2.0（`versionCode=12`）：启动 + `本地核心已就绪` 通过；但本轮上游播放接口连续空响应（`anonymous response was empty`，设备注册正常），APK 端无法验证真实出画面——属 D-47 上游限流，不是本轮代码回归。

> 结论：**电脑端"看起来一直很快"，很大一部分是它那 1.86GB 缓存兜住了。** 手机端这条线现在也能吃到同一批缓存；APK 独立模式要自己攒缓存，前提是上游肯给流（登录态或限流恢复）。

## 13. 安全模型

- **模式 A**：默认 `0.0.0.0` 且无 token → 同一 Wi-Fi 任何设备可调全部接口（D-01）。高危：`POST /settings`（改任意目录）、`/download`（写文件）、`/download/open-dir`（拉起资源管理器）、`/account/session`（注入 Cookie）、`/account/logout`（清库）。
- **模式 B**：只绑 `127.0.0.1`，外部连不上；但 WebView 明文/混合内容/JS 桥全开、无 CSP（D-20）。
- 已做防护（**不要回退**）：id 白名单正则、媒体文件名 `path.basename`、图片代理 https+域名白名单、删除只允许下载目录内、静态托管只认 `WEB_DIST`。

**大改中的安全要求**：界面重构不得放宽任何校验；新增接口必须走 `readJson` + id 校验 + `ok/fail`。

## 14. 代码约定

1. 注释写"为什么"，踩过的坑留在注释里（"两个 moov""NVENC 旧 SDK"是项目最贵的资产，重构时别删）。
2. 上游错误统一过 `toUserMessage`（429 限流 / 502 断网），不要把 stack 丢给前端。
3. 新增页面：`pages/<域>` + `MRoute` + `PAGES` + `LABEL`，hash 别名进 `ALIAS`；**不新开状态管理**。
4. 前端请求统一走 `api/`，组件里禁止直接 `fetch`（分享链接解析例外）。
5. 手机壳内**禁止直接取桌面 store 的 `openDetail`**，统一 `useNav`，桌面视图复用手机壳时用 `useMaybeNav()` 安全回退。
6. 卡片整张可点，内部按钮 `stopPropagation`。
7. 弹层一律 `createPortal` 到 body（祖先 `transform` 会让 `position:fixed` 失效）。
8. 缓存/临时文件一律 D 盘工程内（`.tmp`、`data`），不写 C 盘。
9. **界面改动必须附 390×844 截图**，且与官方同名页并排；没有截图的 UI 改动视为未完成。
