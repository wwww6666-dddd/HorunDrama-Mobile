## 0. 这份文档和 v1 的关系

v1 开发文档描述的主线是「1.1.0 独立化」（把 Node 核心搬进 APK）。那条线现在**重启为发布阻断项**：代码在、包不合格（D-23 占位 ffmpeg / D-24 未上真机），必须先补齐再谈发版（见 §16 阶段 A0）。

v2 把工程明确拆成**两条独立推进的线**，避免互相干扰：

| 线 | 内容 | 状态 | 是否本次主线 |
| --- | --- | --- | --- |
| **A 线：运行时** | 模式 A（PC 核心 + 局域网 WebView）→ 模式 B（APK 内置 Node） | A 可用；B 已编包但 ffmpeg 占位、未上真机 | **是，发布阻断**（"手机独立运行"是硬要求） |
| **B 线：界面与信息架构** | 以官方 7.4.5.32 为基准，重做导航、剧场、推荐、我的、播放、搜索 | 现为 v1 深色玻璃风格，尚未对齐 | **是，本次大改主线** |

两条线必须**在同一版本里同时达标**：UI 对齐是「看起来对」，独立运行是「用起来能活」。凡本文出现「本次」「大改」，默认指 B 线；A 线单独验收，但**独立运行不达标不得发版**。

## 1. 产品定位与边界

### 1.1 定位

**短剧为核心的内容客户端**：当前只做「找剧—看剧—追剧」这一件事，以官方红果短剧的信息架构与视觉为参照，去掉一切与观看无关的商业模块。后续可扩展到小说 / 听书 / 漫画 / POV 文本（C 档，见 §1.2），但**短剧始终是唯一主线**，扩展不改变底栏与信息架构。

### 1.2 能力边界（三档）

**A 档 · 明确不做（写死，不接受"先加上再说"）**

| 官方能力 | 处理 |
| --- | --- |
| 福利页 / 金币 / 现金提现 / 打卡任务 | **不做**，底栏不设福利位 |
| 开屏广告、激励视频、信息流广告位、曝光上报 | **不做**，接口层不接广告字段 |
| 商城（bookmall）、游戏（minigame）、社区动态、订单 | **不做** |
| 支付 / 会员 / VIP / 钻石 | **不做** |
| 青少年模式 | **暂不做**（无账号年龄体系，等账号链路稳定后再议） |

**B 档 · 本次大改做（B 线）**

首页推荐流、剧场（找剧/筛选/榜单/新剧/预约）、搜索、播放（弹幕/评论/倍速/选集）、详情、我的（历史/收藏/点赞/预约）、追剧、下载、设置。

**C 档 · 可以做，但后续单独立项（不进本次 UI 主线）**

| 能力 | 定位 | 接入前必须先解决的事 |
| --- | --- | --- |
| 推送（新集提醒） | 阶段 D | **沿用 PC 核心那套，不自建厂商通道**：核心已有新集检查（`notifyNewEpisodes`），手机独立运行时由本机核心定时检查 + 本地通知；PC 在线时也可由 PC 侧检查后走现有接口同步。**前提是模式 B 达标——推送不许依赖"PC 一直在线"** |
| 热修复 | 阶段 D | 前端天然可热更：远端 `dist` 清单 + 哈希校验 + 原子切换（核心本来就托管 `dist`）；**原生层不做 Tinker 类补丁**，只做壳内资源与前端替换 |
| 多进程 | 阶段 D | 播放/下载拆 `:player`/`:downloader` 需 AIDL/Messenger；SQLite WAL 已能多进程，但当前核心是单 Node 进程，拆之前要先评估收益（现在单进程并未成为瓶颈） |
| Lynx/H5 动态页 | 阶段 D | 低成本方案＝远程 HTML + 域名白名单 + **不给 JS 桥**；真上 Lynx 引擎要引 SDK 与包体（官方那套 1,583 类的 `com/lynx/tasm` 不建议照搬） |
| 小说 / 听书 / 漫画 / POV 文本 | 阶段 D | 上游 `openhongguo` 是否暴露这些域**尚未验证**，这是前置；验证通过后需新增 `sources/novel|audio|comic`、阅读器（字号/夜间/翻页）与音频播放器（后台播放 + `MediaSession`） |

#### 扩展位约定（C 档接入时的硬规则，现在就把位留出来）

1. **API 按域挂**：`/api/novel/*`、`/api/audio/*`、`/api/comic/*`、`/api/push/*`、`/api/ota/*`，不塞进现有目录接口。
2. **路由按域开**：`#/novel`、`#/audio`、`#/comic`、`#/pov`，与 4 个底栏 Tab **解耦**——底栏不因为新增域变长。
3. **页面按域建目录**：`pages/novel`、`pages/audio`…（见 §4.2），沿用"一个域一个目录"的重组原则。
4. **设置只加不写死**：新增开关一律进 `settings.json` + `/api/settings`，前端读配置，不在组件里硬编码。
5. **数据表按域分**：`novel_progress` / `audio_progress` 独立于 `progress`，短剧进度不被别的域污染。
6. **任何新增域都不得把广告位、福利、曝光上报字段带进接口**——A 档边界优先于 C 档便利。
7. **所有能力必须在"无 PC 在线"下自洽**：登录、数据、推送、阅读/收听进度都不许回落到 PC 核心；PC 只作为可选加速与调试环境。

### 1.3 运行模式

- **模式 A（开发/调试用）**：电脑跑 `mobile-core`，手机 WebView 经局域网加载 `dist`。手机与电脑同一 Wi-Fi，电脑关机则手机不可用。**仅用于开发期联调，不作为交付形态。**
- **模式 B（目标形态 · 硬要求）**：APK 内嵌 Node 24 + 核心 + 前端 + ffmpeg，手机 `127.0.0.1:5881` 独立运行。当前 1.1.0 包内 `libffmpeg.so` 是占位文件，需补 mini ffmpeg 重编后验收。
- **"手机独立运行"的具体口径**：拔掉电脑 / 关 Wi-Fi / 飞行模式（本地网）下，仍能启动、保留登录态、播放、下载、收到新集提醒；登录方式（扫码/短信）与数据接入（`openhongguo`）沿用原有那套，不新开通道。

B 线与本文的 UI 改造无耦合：前端始终只走 `/api/*`，界面层不需要知道核心跑在哪台机器上（这一点必须守住，否则模式切换会撕开两套 UI）。

### 2.2 结构事实（拆包结论，摘要）

- 26 个 dex、**350,223 个类**、121 个 `.so`，**`res/layout` = 0**：界面是 Compose 自绘，**没有 XML 布局可以照抄**。
- `com/dragon/read` 135,212 类，其中 `component` 40,425 / `kmp` 32,595 / `rpc+pbrpc` 25,219 —— 四分之三是基座，页面只是壳。
- 与界面直接相关的模块：`polaris`(首页 1,205)、`pages`(1,057)、`feed`(200)、`video`(190)、`leftslidepage`(我的 204)、`story`(495)、`search`(16)。
- 剧场是**模型驱动瀑布流**：`BookMallCellModel`（卡片内容）/ `SlideListPlacer`（排布）/ `DoubleRowMarginConfig`（双列边距）/ `InfiniteCell`（无限流）。
- 底栏是**配置驱动**（`feed/bookmall/bottomtab/SeriesMallPageConfig`），每个 tab 配一套 lottie（`assets/main_bar_lottie/*`）。
- 播放器与弹幕分属两个包：`video/BaseVideoView`、`video/IVideoDataProvider`、`video/api/ISessionPlayAction`（连播=会话级动作）、`video/danmaku/*`。
- 素材规范：数字用 `DouyinNumberJR-Medium123.ttf`，标题用 `DouYinFaXianSansBold.ttf`。

> 完整拆解见《官方结构拆解与手机端整改规划.md》第 1 节；逐屏布局与坐标见《红果官方App对照扫描.md》第 3 节。

## 6. 信息架构（本次大改的核心）

### 6.1 底栏：4 个纯文字 Tab

```
首页(feed)  ·  剧场(home)  ·  追剧(library)  ·  我的(me)
```

- 官方是「首页/剧场/福利/我的」；A 档去掉福利位，第四位给「追剧」（官方把它藏在"我的-追更"里，我们独立出来更好找）。
- 选中态：**字重 600 + 颜色反转 + 1px 下划线**；不设图标、不设药丸、不设角标。
- 高度 44dp + `env(safe-area-inset-bottom)`；未选中 `#8A8F99`，选中浅底用 `#161823`、深底用 `#FFFFFF`。
- **阶段 A 已落地**：`nav.tsx` 的 `TABS` 改 4 项（首页 feed / 剧场 home / 追剧 library / 我的 me）；`TabBar` 删掉图标与药丸滑块，栏高 44dp + 安全区，未选中 `color-mix(--m-text 45%)`、选中 600 字重 + 18×1px 下划线。

### 6.2 路由表（hash，全部保留）

| 类型 | 路由 | 说明 |
| --- | --- | --- |
| Tab | `#/feed` / `#/` / `#/library` / `#/me` | 4 个底栏页 |
| 二级 | `#/rank` `#/search` `#/new` `#/category` `#/downloads` `#/about` | 顶栏返回式页面 |
| 详情 | `#/series/<id>` | 底部抽屉（Sheet，portal 到 body） |
| 播放 | `#/play/<seriesId>/<episodeId>/<no>[?t=秒]` | 全屏，无底栏 |
| 小窗 | `#/mini/<seriesId>/<episodeId>/<no>?t=秒` | 迷你播放器 |
| 预留（C 档，阶段 D） | `#/novel/<bookId>/<chapter>` `#/audio/<albumId>` `#/comic/<id>` `#/pov/<id>` | 接入时才实现；**4 个底栏 Tab 不因新增域变长** |

**兼容别名（不可删）**：`theater → home`、`settings → me`、`persons → rank`、`home → home`、`newreleases → new`。
**禁止改动**：`playHash` / `miniHash` / `parsePlay` / `parseMini` 的格式——分享续播链接已在用户手里。

### 6.3 入口重分配（官方做法 vs 我们）

## 9. 核心链路（B 线不动这里，改动需单独评审）

### 9.1 播放决策（`media/jobs.ts`）

`/api/play/:episodeId` 返回 job（ready / queued / working），前端轮询 `/api/prepare/:jobId`。优先级：

1. 本地转码命中（`mode=file`）；
2. 指定高清未命中但低档已缓存 → 先播低档 + 后台升档（返回 `upgradeJobId`）；
3. `wait=1` → 起 App 源转码任务，前端轮询；
4. 官网 360p 直连（`/api/stream/:episodeId` 代理，浏览器直连会 403）；
5. 秒开流（`/api/live`，无完整时长、不可拖）；
6. 慢路径：整集下载 + ffmpeg 转码。

关键约束（**重构界面时不许碰**）：同集同档 `INFLIGHT` 合并；前台转码不限并发、后台一次一个；升档后原位换源并保留播放位置；默认 `quality=1080p + wait=1`。

### 9.2 转码（`media/transcode.ts`）

`取流 → 下载加密原件 → ffmpeg → .part.mp4 → 时长/box 校验 → rename`。
进度 0~0.45 下载、0.45~0.99 转码、1 完成。能 copy 就 copy（H.264 或可硬解 HEVC 时 `-c copy`）；编码器 `h264_nvenc → h264_amf → libx264`，必须真编一帧才算可用；产物校验 `mvhd` 时长差 ≤3s、`moov` 恰好 1 个。

### 9.3 缓存

| 缓存 | 上限 | 清理 |
| --- | --- | --- |
| 转码视频 | 4096MB（`settings.mediaCacheMB`） | 完成后 `pruneMediaCache`；`/api/cache/clear` 只删受管文件名 |
| 封面 | 96MB | LRU |
| 直连地址 | 内存 400 条 / 提前 60s 过期 | 403 时重取 |
| 目录数据 | 内存 TTL | **首页/推荐流 180s**（阶段 0 由 120s/60s 上调，限流期靠缓存顶住首屏）；搜索联想 60s、详情/榜单 120s |

> 已知：`CACHE_LIMIT` 在模块加载时固化，改上限需重启（D-07）。

### 9.4 账号与本地库

- 三类身份分开：`app-device.json`（匿名）/ `session-device.json`（账号设备）/ `session.json`（登录态，可选 AES-256-GCM）。
- 写操作顺序：**先写账号，成功再改本地**；收藏失败回滚本地。
- SQLite（WAL）：`progress / favorite / liked / follow / reservation / download`；`progress` 以剧为主键，只记"看到哪集、第几秒"。
- **退出登录会清空本地 5 张表**（D-03），大改中必须改成"只清会话"。

### 9.5 下载

并发 1~4（默认 2）；优先 App 源转码，失败退 360p 直连；路径 `<downloadDir>/<剧名>/第N集-<档位>.mp4`；暂停/取消用 `AbortController`；恢复从 0 重下（D-13）。

### 9.6 上游失败与退避（阶段 0 新增，界面重构时不许回退）

`sources/client.ts` 的 `withRetry` 是所有目录类调用（首页/推荐流/搜索/筛选/榜单/详情/弹幕）的统一入口，策略集中在这里，调用方不再各自 sleep：

| 项 | 值 | 理由 |
| --- | --- | --- |
| 尝试次数 | 默认 **3**（播放链路显式传 1） | 限流/空响应多为瞬时；播放要立刻退化到 360p，不能干等 |
| 退避 | 800ms 起、`2^n` 递增、**8s 封顶**、±15% 抖动 | 固定间隔会形成同频重试；抖动把并发请求错开 |
| 上游建议 | 有 `retryAfterMs` 时取「退避值 / 建议值」较大者（同样 8s 封顶） | 尊重服务端，又不为一个目录请求挂几十秒 |
| 设备轮换 | 仅 `ANONYMOUS_LIMITED` / `DEVICE_REJECTED` 调 `client.resetDevice()`（重写 `data/app-device.json`） | 匿名空结果换身份才有用；`RATE_LIMITED` 换身份无效（实测） |
| 轮换冷却 | **90s** 内只换一次 | 每次失败都注册新设备会连着打注册接口，反而更像异常客户端 |
| 判为瞬时 | `ANONYMOUS_LIMITED` / `RATE_LIMITED` / `DEVICE_REJECTED` / `TRANSPORT` / message 含 empty·timeout·ECONNRESET | 参数错误、已下架必须原样抛出，不许吞 |
| 目录缓存 | `home` 180s、`feed` 180s（其余 60~120s） | 宁可给 3 分钟前的榜单，也不给空屏 |

上游最终仍失败时，接口照旧返回 `429 upstream_limited` / `502 upstream_down`，前端按错误态展示——**不要把失败伪装成空列表**。

## 13. 安全模型

- **模式 A**：默认 `0.0.0.0` 且无 token → 同一 Wi-Fi 任何设备可调全部接口（D-01）。高危：`POST /settings`（改任意目录）、`/download`（写文件）、`/download/open-dir`（拉起资源管理器）、`/account/session`（注入 Cookie）、`/account/logout`（清库）。
- **模式 B**：只绑 `127.0.0.1`，外部连不上；但 WebView 明文/混合内容/JS 桥全开、无 CSP（D-20）。
- 已做防护（**不要回退**）：id 白名单正则、媒体文件名 `path.basename`、图片代理 https+域名白名单、删除只允许下载目录内、静态托管只认 `WEB_DIST`。

**大改中的安全要求**：界面重构不得放宽任何校验；新增接口必须走 `readJson` + id 校验 + `ok/fail`。

## 14. 代码约定

1. 注释写"为什么"，踩过的坑留在注释里（"两个 moov""NVENC 旧 SDK"是项目最贵的资产，重构时别删）。
2. 上游错误统一过 `toUserMessage`（429 限流 / 502 断网），不要把 stack 丢给前端。
3. 新增页面：`pages/<域>` + `MRoute` + `PAGES` + `LABEL`，hash 别名进 `ALIAS`；**不新开状态管理**。
4. 前端请求统一走 `api/`，组件里禁止直接 `fetch`（分享链接解析例外）。
5. 手机壳内**禁止直接取桌面 store 的 `openDetail`**，统一 `useNav`，桌面视图复用手机壳时用 `useMaybeNav()` 安全回退。
6. 卡片整张可点，内部按钮 `stopPropagation`。
7. 弹层一律 `createPortal` 到 body（祖先 `transform` 会让 `position:fixed` 失效）。
8. 缓存/临时文件一律 D 盘工程内（`.tmp`、`data`），不写 C 盘。
9. **界面改动必须附 390×844 截图**，且与官方同名页并排；没有截图的 UI 改动视为未完成。
