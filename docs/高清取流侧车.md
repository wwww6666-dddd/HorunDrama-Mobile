# 高清取流侧车（hg-resolve）

> 1.3.2 起，手机端真实 1080p 依赖本侧车；不再依赖旧纯 JS `pure-sign`。

## 为什么需要

2026-11-23 上游播放接口改了请求校验。旧 JS 签名（`x-helios` / `x-medusa`）仍能过一部分校验，但 `video_tab/multi_video_model` 返回 **HTTP 200 + 0 字节**。`11111` 1.2.32 能取到 1080p，是因为它内置了 **MetaSec v5 + SDI 会话令牌**，不是换了新端点。

## 来源与许可

- Rust workspace：`NeeYoonc/hongguo-web-player` 的 `nas/vendor`（`hg-resolve`、`hongguo-signer`、`metasec`、`sdi`）。
- MetaSec 材料：官方客户端 `7.4.3.32` 的 `image.elf`（4,501,136 B）与 `license.txt`（304 B），放在 `.tmp/hgresolve/metasec/`，不进 Git。
- `hg-resolve` 采用 **PolyForm Noncommercial 1.0.0**；`image.elf` / `license.txt` 来自官方客户端。个人自用/研究可用；公开商业分发前必须自行确认授权，或只分发自有代码、不打包官方材料。

## 构建

```bash
# Linux 主机侧车（调试）
cargo build --release -p hg-resolve

# Android（NDK r28c）
rustup target add aarch64-linux-android x86_64-linux-android
CC_aarch64_linux_android=$NDK/toolchains/llvm/prebuilt/linux-x86_64/bin/aarch64-linux-android24-clang \
AR_aarch64_linux_android=$NDK/toolchains/llvm/prebuilt/linux-x86_64/bin/llvm-ar \
cargo build --release -p hg-resolve --target aarch64-linux-android
# x86_64 同理，把 target/CC/AR 换成 x86_64
```

产物放：

```text
.tmp/hgresolve/arm64-v8a/libhgresolve.so
.tmp/hgresolve/x86_64/libhgresolve.so
.tmp/hgresolve/metasec/image.elf
.tmp/hgresolve/metasec/license.txt
```

`android/build.ps1` 会把它们分别复制到 `jniLibs/<abi>/libhgresolve.so` 与 `assets/core/vendor/hgresolve/metasec/`；`NodeCore.java` 启动时设置：

- `HORUN_HGRESOLVE=<nativeLibraryDir>/libhgresolve.so`
- `HONGGUO_METASEC_DIR=<files>/core/vendor/hgresolve/metasec`

设备档案首次注册后保存在 `<files>/data/hgresolve/device.json`，后续复用。

## 调用约定

```bash
hg-resolve 0 <video_id> <definition> --ct 1004 --device <device.json>
```

- `series_id=0` + `--ct 1004`：跳过详情请求，直接按短剧类型取流；真人剧/漫剧实测都返回 1080p。
- 输出一行 JSON；`ok:true` 时含 `url`、`cenc_key_hex`、`qualities`、`definition`、`codec`、`encrypted`。
- 失败返回 `{"ok":false,"error":"..."}`；Node 侧会回退旧 App 源，再回退官网 360p。

## 验证

```bash
# 侧车直取
HONGGUO_METASEC_DIR=.tmp/hgresolve/metasec \
  .tmp/hgresolve/hg-resolve 0 7699808700382317592 1080 --ct 1004 --device /tmp/device.json

# 3 秒样本
ffmpeg -decryption_key <cenc_key_hex> -t 3 -c copy sample1080.mp4
ffprobe -v error -show_entries stream=codec_name,width,height -of default=nw=1 sample1080.mp4
```

期望：`codec_name=hevc`、`width=1920`、`height=1080`。

## 1.3.2 打包与播放注意

- 1.3.2 的 `transcode.ts` 不再用 `-progress pipe:1`：APK 内置精简 ffmpeg 没编 `pipe` 协议，旧参数会在任务 0.45 处直接失败。进度改为读 stderr 的 `time=HH:MM:SS`。
- 同一份精简 ffmpeg 只有 `libaom-av1/aac/ac3/flac/libmp3lame/opus`，**没有 libx264**；不能硬解 HEVC 的设备不会得到 1080p H.264，`startAppJobInner` 会在起任务前预检并回落官网 360p，不伪造高清。
- 模拟器验证：`/api/play/7699808700382317592?quality=1080p&wait=1&hevc=1` → `ready`，媒体 11,699,879 B，`ffprobe` 为 `hevc 1920x1080 / 195.95s`；App 内 `<video>` `readyState=4`、`paused=false`。

## 排障

1. `/api/health` 的 `hgResolve` 为 `false`：侧车或 MetaSec 材料没就位。先看 `libhgresolve.so` 是否在 `nativeLibraryDir`、`image.elf`/`license.txt` 是否释放到 `core/vendor/hgresolve/metasec`。
2. 侧车启动即失败：用 `adb logcat -s HorunCore` 看 `hgresolve` stderr；常见是 `libc++_shared.so` 缺失或 ABI 不匹配。
3. 取流空响应：确认 `device.json` 已注册、设备档案未被上游拉黑；同一设备连续请求要保留 1.5s 间隔。
4. 真机播放黑屏：先看 `/api/play/<vid>?quality=1080p&wait=1&hevc=1` 是否 `ready`，再看 `ffprobe` 生成文件是否 hevc；若设备不支持 HEVC，1.3.2 会回落官网 360p（内置 ffmpeg 无 H.264 编码器），不会伪造 1080p。
